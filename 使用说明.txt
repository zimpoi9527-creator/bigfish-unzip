================================================================
  大肥鱼解压  （多层伪装包一键解压）
  基于开源项目 Complex-Unzip-Tool 改造
================================================================

【启动】
  · 图形界面：双击  大肥鱼解压.exe
  · 命令行：  把文件/文件夹拖到  大肥鱼解压-命令行.exe  上
  · 源码运行：双击  拖到这里解压.bat（需本机 Python 3.10+）

  程序目录下的 7z\ 是内置的 7-Zip 引擎，别删；passwords\ 是密码库。

  · 左侧是阿罗娜立绘 + 「拖到这里」提示，拖拽时会出现蓝色高亮框；

  按物理像素渲染，文字是原生抗锯齿，不会出现被系统位图放大后的锯齿和发虚。

【解压失败原因报告】
  每次解压失败都会在日志里给出「原因 + 建议 + 7-Zip 原始输出」，例如：

    [ERROR] 解压失败：合同.pdf —— 密码错误
    [INFO]         建议：把正确密码填进密码框；密码多的话写进 passwords/0_temp.txt 并勾选“使用密码库”
    [DEBUG]        7-Zip: ERROR: Wrong password : a.txt | Archives with Errors: 1

  目前已能识别的失败类型：
    · 密码错误
    · 数据校验失败（CRC 不匹配，包损坏）
    · 压缩包不完整（截断 / 缺少分卷）
    · 不是有效的压缩包（改后缀的普通文件等）
    · 压缩算法不受支持
    · 没有读写权限
    · 找不到文件或缺失分卷
    · 磁盘空间不足
    · 内存不足
    · 文件被其他程序占用
    · 其他未知错误（附原始输出，便于排查）

  一次任务结束后，如果有失败项，会在「输出目录」（或第一个被拖入文件所在目录）
  生成一个 解压失败报告.txt，里面逐条列出：文件名 / 原因 / 建议 / 7-Zip 原始输出 / 路径。
  界面日志最后也会给出失败原因汇总。

【关于关闭】
  · 解压进行中直接点 × 会立即取消任务并退出（不再弹确认框，
    避免"点了没反应"的假死感）；
  · 关闭时最多等 2.5 秒让后台收尾，若仍有线程/子进程拖着，
    4 秒后强制结束进程，保证不会在任务管理器里留下僵尸；
  · 正在解的那个包会被中断，暂存区自动清理，不会破坏原始压缩包。

【界面字体】
  界面用的是 Fira Code（GitHub 上星数最高的编程字体，8.2 万 ★）。
  · 字体文件随程序放在 assetsonts\ 下，启动时以「私有字体」方式加载，
    不写注册表、不安装到系统，换个文件夹拷走也不会失效；
  · 中文 Fira Code 没有字库，会自动回退到系统里的中文字体（雅黑等）；
  · 想换字体：把新的 .ttf 丢进 assetsonts\，再改 unzip_gui.py 里
    FONT_FAMILY_TARGET = "字体族名" 即可；字体族名可用系统「字体设置」查看。

【四个开关 / 选项】

  ① 解压到（输入框 + 浏览… 按钮）
       · 留空：解压到压缩包所在目录（默认）
       · 选了目录：产物统一放到该目录下
     命令行： --out "D:\目标目录"

  ② 解压到单独文件夹（默认勾选）
       · 勾选：目标目录下再建一个与压缩包同名的文件夹
               重名自动变成 资料_1、_2 …
       · 不勾选：文件直接铺在目标目录里（重名自动加 (1)）
     命令行： --no-separate

  ③ 完成后删除压缩包（默认不勾选）
       · 解压成功后删除原始压缩包；分卷包整组删除
       · 失败或产出为空时一律不删
     命令行： --delete-source

  ④ 自动识别并解压二级压缩（默认勾选）★本次新增
       · 解完第一层后，扫描产物里是否还有压缩包（二级/嵌套包）；
       · 如果嵌套包的扩展名是伪装的（如 内层资料.jpg 其实是 zip），
         会先把它重命名成真实后缀（内层资料.zip），再继续解压；
       · 层级不限，一直解到最内层；
       · 重命名记录会出现在右侧「分卷识别 / 改名」表里，说明列写“二级压缩”；
       · Office / ePub / JAR / APK 等本身就是 ZIP 容器的正常格式不会被误改名，
         .exe/.dll 等可执行文件也不会；
       · 关闭后只解第一层。
     命令行： --no-recursive

【日志里怎么看二级压缩】
  [INFO] 检测到二级压缩: '内层资料.jpg' 实为 zip，已重命名为 '内层资料.zip'
  [INFO] 分析完成，发现 1 个二级压缩任务。
  [SUCCESS] 二级压缩：本次识别并重命名 1 个嵌套包（已解压）
  [SUCCESS] 全部完成：成功 1 个，失败 0 个，二级压缩 1 个。

【密码库】
  passwords\0_temp.txt  临时密码本，一行一个密码
  passwords\1_all.txt   主密码库，成功过的密码自动追加
  passwords\其他.txt    自己新建即可，自动出现在列表里
  命令行版密码本菜单编号从 0 开始：[0] 是 0_temp.txt。

【命令行版参数】
  大肥鱼解压-命令行.exe [选项] 文件或文件夹 [更多路径…]
    --out DIR        解压到指定目录
    --no-separate    不再套一层同名文件夹
    --delete-source  成功后删除原始压缩包
    --no-recursive   只解第一层，不识别二级压缩

【它比原版强在哪】

  1. 完全按文件内容（魔数）识别格式，扩展名是 .pdf/.jpg/随便什么都行；
  2. 分卷无论哪一卷被改成什么后缀，都能自动聚合成一组再解压：
       情形一  a.jpg + a.002~004                （第一卷改名，基名相同）
       情形二  part1.jpg + inner.zip.002~004    （第一卷改名，基名不同）
       情形三  v1.jpg v2.jpg v3.jpg v4.jpg      （全部卷都乱名）
       情形四  x.001 / x.part1.rar / x.z01 / x.r00（标准命名）
     只有两卷（第二卷更小）的情况也支持；
  3. 分卷通过「影子目录 + NTFS 硬链接」拼成 001/002…，
     不复制数据、不重命名、不修改用户原始文件；
  4. 文件夹拖拽时先扫描分卷集合再逐组处理，多个文件一起拖时同一组只解一次；
  5. 先按普通压缩包解，失败才尝试分卷拼合，正常包不会被误判；
  6. 支持加密分卷；密码库自动学习。

【已知限制】
  · 全部卷都被改成乱名、且目录里混有无关的同尺寸文件时，卷序可能推断错，
    此时会报错跳过，不会损坏任何文件；
  · 分卷集合必须完整（第一卷 + 后续所有卷在同一目录）；
  · 依然只支持 7-Zip 能识别的格式；
  · 二级压缩识别后，中间层压缩包在解压成功后会被清理（最终只留最内层内容）；
    重命名过程记录在日志和改名表里；
  · WinZip 分卷（.z01 开头、.zip 结尾）逻辑上支持但未实测。
